This project is the current working R200 build for **Diablo II: Resurrected Classic Offline**.

Target build: **v1.6.81914**

The patcher is a zero-flag runner. Normal execution is:

```bat
python patcher.py
```

`patch.bat` may also be used when present.

## Folder layout

Keep the working folders beside `patcher.py`:

```text
C:\D2Rmod\
├─ patcher.py
├─ patch.bat
├─ README.md
├─ vanilla\
├─ static_mod\
├─ patch_sources\
└─ output\              <- generated by the patcher
```

`vanilla\` must contain the extracted vanilla `data\` tree.

The patcher regenerates the mod from the vanilla source data and writes the result under:

```text
C:\D2Rmod\output\mods\qol\qol.mpq\
```

## Regular Cow Level drop system

Regular Hell Bovines use the Stage 4 direct flat mixed R200 drop architecture.

The deterministic cow-pool seed is:

```text
1782137524
```

The standard pool partition size is:

```text
45
```

Eligible normal, exceptional, and elite base codes are combined into one flat mixed pool with equal per-code weighting. Quest/restricted bases and known Classic-unsafe generic charm/rune/jewel routes are filtered.

Ancient Armor and Sacred Armor remain available with the same per-code weighting as other eligible bases.

### Current regular-cow top-level weighting

The active regular-cow wrapper is:

```text
zz_cow_allbases_wrap_FLAT
```

Its three current branches use equal weight:

```text
R200 flat mixed pool                         8192
zz_classic_sunder_torch_unique_cow_drop     8192
zz_classic_annihilus_unique_cow_drop        8192
```

Therefore the top-level regular-cow selection is:

```text
R200 pool : Hellfire Torch : Annihilus
   8192   :      8192      :    8192
```

The Torch and Annihilus branches remain controlled **unique-only** routes. Their raw charm bases are not added to the generic mixed base pool.

## Cow King

Cow King is deliberately excluded from the regular-cow direct sampler.

His native boss TreasureClass behavior is preserved. The regular R200 flat pool, Hellfire Torch sidecar, and Annihilus sidecar are not injected into the Cow King route.

The existing R200 Cow XP multiplier remains independent of this loot-routing protection.

## Hellfire Torch — all-Sunder carrier

The real LoD **Hellfire Torch** is used as the stable Classic all-Sunder carrier.

Base:

```text
cm2 / Large Charm
```

The vanilla Torch properties are cleared and replaced with only:

```text
pierce-immunity-cold
pierce-immunity-fire
pierce-immunity-light
pierce-immunity-poison
pierce-immunity-damage
pierce-immunity-magic
```

Each property uses:

```text
value = 300
```

There are no negative resistance penalties.

The Torch is exposed to regular cows through:

```text
zz_classic_sunder_torch_unique_cow_drop
```

Old Sunder cube-test recipes are removed from generated output.

## Annihilus

The real LoD **Annihilus** is ported to Classic through a controlled unique-only regular-cow route.

Base:

```text
cm1 / Small Charm
```

Drop TC:

```text
zz_classic_annihilus_unique_cow_drop
```

`cm1` is not inserted into the generic R200 base pool. This avoids the known unsafe plain Small Charm generation path while still allowing the complete Annihilus unique item to drop.

The direct-wrapper routing is active, so Annihilus is reachable from the same regular-cow top-level wrapper as the R200 pool and Hellfire Torch.

## Javelins

Regular javelin bases use the proven stackless spear-like Classic-safe profile instead of the original throwable/stackable `jave` route.

Supported codes:

```text
jav pil ssp glv tsp
9ja 9pi 9s9 9gl 9ts
7ja 7pi 7s7 7gl 7ts
```

Unsafe quantity-only unique properties are removed where required:

```text
rep-quant
stack
```

## Amazon-specific items

Amazon-specific item support is enabled.

Amazon bows use the normal bow profile:

```text
am1 am2 am6 am7 amb amc
```

Amazon spears use the normal spear profile:

```text
am3 am4 am8 am9 amd ame
```

Amazon javelins use the stackless spear-like profile:

```text
am5 ama amf
```

This gives items such as Titan's Revenge a Classic-safe route. Quantity-only properties may be stripped where required by the stackless conversion.

## Holy Fire / Holy Freeze / Holy Shock

All three elemental Paladin auras use flat damage based on their former maximum value.

Pulse damage copies the maximum progression into the minimum progression:

```text
EMax     -> EMin
EMaxLev1 -> EMinLev1
EMaxLev2 -> EMinLev2
EMaxLev3 -> EMinLev3
EMaxLev4 -> EMinLev4
EMaxLev5 -> EMinLev5
```

The passive weapon-added damage is flattened by copying:

```text
passivestat2 -> passivestat1
passivecalc2 -> passivecalc1
```

The tooltip is reduced to one direct numeric damage value using:

```text
exma*((100+par6)/100)
```

The duplicate damage-range line is removed.
